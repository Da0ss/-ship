# ТЗ: Автоплатёж за коммунальные услуги

Учебный документ для проверки агента на втором ТЗ. В текст заранее заложены дефекты; их список — в tests/golden/autopay.golden.json.

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Проект | Автоплатежи в мобильном банке |
| Заказчик | Департамент розничного бизнеса |
| Версия | 0.3 |
| Статус | Черновик |

## 2. Назначение

Клиент подключает автоплатёж за коммунальные услуги, и банк сам оплачивает счёт каждый месяц. Сервис должен работать быстро и удобно для клиента.

## 3. Термины

- Автоплатёж — регулярное списание с карты клиента в пользу поставщика услуг.
- Поставщик — организация из справочника поставщиков банка.
- Счёт к оплате — сумма, которую поставщик выставил за расчётный месяц.

## 4. Бизнес-требования

**ТЗ-1.** Клиент создаёт автоплатёж: выбирает поставщика, лицевой счёт, карту списания и день месяца от 1 до 31.

**ТЗ-2.** В выбранный день в 09:00 система запрашивает у поставщика счёт к оплате и списывает его сумму с карты клиента.

**ТЗ-3.** Максимальная сумма одного автоплатежа — 500 000 ₸. Если счёт больше, платёж не проводится.

**ТЗ-4.** Если на карте недостаточно средств, система повторяет списание до 3 раз с интервалом 4 часа.

**ТЗ-5.** После успешной оплаты клиент получает SMS с суммой и названием поставщика.

**ТЗ-6.** Клиент может приостановить, изменить и удалить автоплатёж, а также посмотреть историю списаний, выгрузить её в PDF и отправить квитанцию на e-mail.

Система должна быть надёжной и выдерживать высокую нагрузку.

Данные автоплатежей хранятся в таблице AUTOPAY_RULES в Oracle, статус хранится в колонке STATUS_CD типа NUMBER(2).

## 5. Уведомления

Все уведомления по автоплатежам отправляются только push-сообщениями в мобильном банке.

Если списание не удалось, клиенту отправляется уведомление с причиной.

## 6. Обработка ошибок списания

При отказе процессинга с кодом «недостаточно средств» сервис автоплатежей повторяет списание 5 раз, после чего помечает платёж как неуспешный.

При ответе поставщика «счёт не найден» платёж пропускается до следующего месяца.

## 7. API сервиса автоплатежей

### 7.1. Создание автоплатежа

| Параметр | Значение |
|---|---|
| Метод | GET |
| URL | /autopay/create |
| Описание | Удаление автоплатежа клиента |

Пример вызова:

`curl -G "$BASE/autopay/create" -H "Authorization: Bearer $TOKEN" --data "cardNumber=4400430012345678&providerId=17&account=100200&day=31&amount=45000"`

**Content-Type:** application/json.

Тело запроса не используется.

#### Параметры запроса (query)

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| cardNumber | string | Да | Номер карты списания |
| providerId | integer | Да | Идентификатор поставщика |
| account | string | Да | Лицевой счёт у поставщика |
| day | integer | Да | День списания, 1–31 |
| amount | integer | Нет | Лимит суммы, ₸ |

#### Ответ

| Поле | Тип | Описание |
|---|---|---|
| autopayId | string | Идентификатор автоплатежа |
| amount | string | Лимит суммы, ₸ |
| status | string | ACTIVE / PAUSED |

#### Коды ответа

Успешный ответ — 200 или 202. Ошибка параметров — 400. Нет доступа — 401.

**200.** Автоплатёж создан.

**400.** Неверные параметры запроса.

**401.** Клиент не авторизован.

## 9. Критерии приёмки

| Сценарий | Входные данные | Ожидаемый результат |
|---|---|---|
| Успешный автоплатёж | Счёт 45 000 ₸, на карте 100 000 ₸ | Списано 45 000 ₸, SMS отправлено |
